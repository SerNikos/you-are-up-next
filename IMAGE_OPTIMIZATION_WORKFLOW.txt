IMAGE OPTIMIZATION WORKFLOW
===========================

Purpose
-------
This project creates responsive AVIF and WebP copies of raster images while keeping the original source files unchanged.

Current settings
----------------
- Input folder: src/assets
- Supported source extensions: png, jpg, jpeg, webp, gif
- AVIF quality: 70
- WebP quality: 85
- Responsive widths: 320, 640, 960, 1280, 1600, 1920, plus the original width when larger
- Generated image folder: public/optimized
- Generated manifests:
  - src/utils/blurhashes.js
  - src/utils/optimizedImages.js

When adding a new image
-----------------------
1. Put the original image inside src/assets.
2. Run:

   npm run generate:blurhashes

3. Check the generated files and the Git diff.
4. For a React image, use LoadingImage instead of a direct img element:

   import LoadingImage from "../LoadingImage/LoadingImage";

   <LoadingImage src={image} alt="Description" />

5. Commit the original and generated files:

   git add src/assets public/optimized src/utils/blurhashes.js src/utils/optimizedImages.js
   git commit -m "Add optimized image"
   git push

Important deployment rule
------------------------
The production build no longer runs image generation automatically. This keeps normal Vercel deployments fast.

Therefore, when adding or changing an image, run the generator locally and commit its output before pushing. Vercel will then copy the already-generated AVIF/WebP files into the production build.

What happens automatically
--------------------------
- npm run dev runs the generator before starting Vite.
- React images using LoadingImage try AVIF first, then WebP, then the original image as fallback.
- LoadingImage chooses a responsive width based on the rendered size and device pixel ratio.
- BlurHash files and the optimized image manifest are regenerated by the generator.

CSS background images
---------------------
CSS backgrounds do not go through LoadingImage. For a CSS background, add the generated AVIF and WebP URLs manually with image-set(), keeping the original as a fallback.

Example:

  background-image: image-set(
    url("/optimized/bg_website-png-960.avif") 1x type("image/avif"),
    url("/optimized/bg_website-png-1920.avif") 2x type("image/avif"),
    url("/optimized/bg_website-png-960.webp") 1x type("image/webp"),
    url("/optimized/bg_website-png-1920.webp") 2x type("image/webp"),
    url("./assets/useful-art/bg_website.png") 1x
  );

Do not use a direct img element when you expect the AVIF/WebP pipeline to apply. Use LoadingImage for React images.

Verification
------------
1. Start the site with npm run dev.
2. Open Chrome DevTools > Network.
3. Enable Disable cache and hard reload with Ctrl+Shift+R.
4. Filter for avif.
5. Confirm requests such as /optimized/example-png-960.avif.
6. A 304 response means the browser used its cache; it does not mean the file is empty.

Quality and size notes
----------------------
The current measured aggregate result for the 64 existing source assets is:
- Original sources: 249.48 MiB
- Largest AVIF variants at quality 70: 20.57 MiB, 91.75% smaller
- Largest WebP variants at quality 85: 28.21 MiB, 88.69% smaller

These percentages describe byte reduction, not a percentage of visual quality lost. AVIF quality 70 is a lossy encoder setting. Review important images at 100% zoom if visual fidelity matters.

The original PNG/JPG/WebP files remain available as source files and fallback files.

Maintenance notes
-----------------
- The generator rebuilds all raster variants, not only the newest image.
- It clears and recreates public/optimized, so review deletions and additions in Git after running it.
- If an image is changed or removed, run the generator again and commit the updated manifests and optimized files.
- If an image is used in CSS, update the CSS image-set URLs when its generated filename changes.
